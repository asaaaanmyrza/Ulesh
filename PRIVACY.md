
# Ulesh — Privacy and Data Protection Plan

## 1. Introduction

Ulesh is an open-source project intended to connect restaurants and charitable organizations in Kazakhstan to facilitate safe food redistribution.

This document describes the project's planned approach to protecting personal information and maintaining data security.

Ulesh is currently in the planning stage. The proposed platform does not yet operate a production service or collect personal data through live user registration.

## 2. Planned Data Collection

The future platform may process the following information:

- Organization name and type.
- Name and contact details of an authorized representative.
- Business email address and phone number.
- Food pickup location.
- Food listing details, including product type, quantity, expiration date, and storage requirements.
- Donation request and pickup status.
- Basic account and security activity records.

Only information necessary for operating the service should be collected.

Sensitive personal information, such as health records or national identification numbers, should not be collected unless a specific lawful and justified need is established.

## 3. Purpose of Data Processing

The planned data processing activities will support:

- Registration and verification of participating organizations.
- Communication between restaurants and charitable organizations.
- Coordination of food donation requests and pickups.
- Prevention of fraud, abuse, and unsafe transactions.
- Maintenance of service security and operational records.

Personal information will not be sold to advertisers or unrelated third parties.

## 4. Data Access and Sharing

Access to personal data should be limited according to each user's role.

For example:

- Restaurants should manage their own food listings and organization information.
- Charitable organizations should access information required to request and collect available donations.
- Contact details should be shared only when necessary for donation coordination.
- Project administrators should receive only the access required for authorized support and security tasks.

Public food listings should not expose unnecessary personal information.

## 5. Planned Security Measures

The future technical implementation is expected to include:

- HTTPS to protect information transmitted between users and the server.
- Secure account authentication.
- Strong password hashing rather than storing plaintext passwords.
- Role-based access control.
- Restricted access to databases and administrative functions.
- Secure management of API keys and other credentials.
- Security updates, backups, and appropriate logging.
- Protection against unauthorized access and accidental data exposure.

These safeguards are proposed requirements and have not yet been implemented or independently audited.

## 6. Data Retention and Deletion

Ulesh intends to retain personal data only for legitimate and necessary purposes.

Before production deployment, the team must define specific retention periods and deletion procedures consistent with applicable laws and operational requirements.

Users should have a documented way to request access to, correction of, or deletion of their personal information, where legally applicable.

## 7. Consent and Legal Compliance

The project aims to comply with applicable data protection requirements, including the legislation of the Republic of Kazakhstan.

Before collecting real user data, the team will determine the lawful grounds for processing, appropriate notices, and consent mechanisms where required.

Additional legal review may be necessary before public deployment.

## 8. Security Incidents

A future incident response procedure should define how the team will identify, investigate, contain, and document security incidents.

Affected users and relevant authorities should be notified when required by applicable law.

Sensitive security reports must not be published in public GitHub Issues.

## 9. Open Source and Personal Data

Ulesh intends to make its software source code publicly available.

However, open-source software does not mean open access to users' personal data.

Passwords, private user records, confidential documents, and production credentials must not be committed to the public GitHub repository.

## 10. Project Status and Future Review

This document is a preliminary privacy and data protection plan for the Ulesh project.

It is not a claim of implemented security controls or a finalized production privacy notice.

The project team must review and update it before operating a live service, including publishing an appropriate contact method for privacy requests.
